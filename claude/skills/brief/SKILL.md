用途（モード）ごとのテンプレートで質問ファイル `./tmp/context.md` を書き起こし、frontmatter の `mode:` で用途を宣言する。宣言したモードは `/ask`・`/grill`・`/design`（と、design が plan.md に転記した先の `/implement`）が読み、既定で優先する観点を切り替える。

**出力先**: `./tmp/context.md`（コミット対象外）。ソースコードは変更しない。

**聞き取りはしない**。テンプレートを書き出し、埋まっていない必須欄を報告して終える。前提を詰めるのは `/grill` の役割で、ここで質問を重ねると工程が重複するため。

## 補助ドキュメント

**必ず読む**:

| 補助ドキュメント | タイミング |
|------------------|-----------|
| `./reference/modes.md` | 手順 1 でモードを検証する時（モード一覧と解決規則の正典） |
| `./reference/modes/<mode>.md` の `## テンプレート` | 手順 3 でテンプレートを書き出す時 |

## パラメーター

`$ARGUMENTS` = `<mode> [題材]`。`<mode>` は `./reference/modes.md` のモード一覧の値。題材は任意で、frontmatter の `title` と H1 に入る。

## 手順

1. **モードを検証する**: 未指定、またはモード一覧に無い値なら、一覧（モードと対象の 1 行）を示して 1 問で尋ねる。題材が未指定なら `{題材}` のまま書き出し、手順 4 の空欄として報告する
2. **既存ファイルを確かめる**: `./tmp/context.md` があれば、**上書き / 追記 / キャンセル** を 1 問で確認する
   - **上書き**: テンプレート全体（frontmatter を含む）で置き換える
   - **追記**: frontmatter はファイル先頭の 1 つだけにする。モードの解決規則は先頭の frontmatter しか読まないので、末尾に足した frontmatter はモードとして効かないため
     - 既存に frontmatter が無い: 先頭に frontmatter を挿入し、テンプレートの本文の節を末尾に足す
     - 既存に frontmatter があり、`mode` が同じ: `mode` は変えず、本文の節だけを末尾に足す。題材が既存の `title` と異なれば `title` を新しい題材に更新し、報告に 1 行書く（`/ask` は `title` で業務シナリオの題材を比べるので、前の題材名のままだと誤った題材と比べてしまうため）
     - 既存に frontmatter があり、`mode` が異なる: どちらの `mode` にするかを 1 問で確認してから、本文の節を末尾に足す
   - **キャンセル**: 何も書かずに終了する
3. **テンプレートを書き出す**: `./reference/modes/<mode>.md` の `## テンプレート` 節のコードブロックの中身を、手順 2 の選択に応じて書き出す（新規・上書きは全体、追記は本文の節だけ）。`{題材}` と `base_commit`（`git rev-parse HEAD` の値）を埋める。テンプレート内の `<!-- -->` コメントは記入の手がかりとして残す
4. **報告する**:
   - `<!-- 必須: … -->` が付いた節のうち、中身がまだ無いものを一覧で示す
   - 次の順を案内する: `/ask ./tmp/context.md` → `/grill ./tmp/context.md` → `/design ./tmp/context.md`。grill にも明示パスを渡すのは、grill が引数を省略すると `./tmp/plan.md` を優先して読むため（前タスクの plan.md が残っていると、宣言したモードが grill に届かない）
   - `./tmp/plan.md` が存在すれば、「前タスクの残骸の可能性がある」と 1 行加える
