スタック内の PR を、選択した範囲まで GitHub の atomic stack merge で一括マージする（選択した PR 以下は全て含まれ、いずれかがマージ不能なら全体が中止される）。破壊的かつ取り消し困難な操作のため、**確認後のみ実行**する。

## 前提条件チェック

詳細は `../stack-pr-init/SKILL.md` の「前提条件チェック（SSOT）」を参照し同じチェックを行う（再宣言しない）。

## 実行プロセス

1. 前提条件チェックを実行する
2. `gh stack view` でマージ対象になり得る PR 一覧（番号・タイトル・状態）を表示する
3. マージ対象範囲（スタック全体、または途中の PR まで）と merge method（merge / squash / rebase）をユーザーに確認する
4. **確認が取れた場合のみ** `gh stack merge <pr-number> --yes --merge-method <method>` を実行する。範囲がスタック全体の場合は PR 番号を省略せず最上位 PR の番号を指定する
5. 完了報告: マージされた PR 番号・タイトルの一覧、失敗時はエラー内容（branch protection 等）をそのまま報告する

`--yes` はステップ 3 でユーザー確認を取った後にのみ付与する。非対話ターミナルでは `--yes` の有無に関わらず確認プロンプトなしで対象範囲全体がマージされる仕様のため、確認の実効性は本 skill のステップ 3 に委ねられる — ステップ 3 を経ずに `gh stack merge` を実行しない。
