# PR 本文テンプレート

`/create-pr` Phase 5 で PR 本文を生成する際の構成。`.github/PULL_REQUEST_TEMPLATE.md` のフォーマットに従う。

**Notion Page ID の処理**は `SKILL.md` の「Notion Page ID によるリファレンス付与」を参照（抽出ルールと本文構造例はそちらが SSOT。本ファイルでは再宣言しない）。

テンプレート構成:

```markdown
## 📝 PR 概要 📝

- **目的**:
  - [機能追加/仕様変更/バグ修正/リファクタリング]
- **関連リンク**:
  - [関連する Issue、Notion、Figma など]
- **変更点の概要**:
  - [主要な変更内容を箇条書き]

## grill 決定からの変更

- [実装が `tmp/grill.md` / `tmp/scenario.md` の照合対象と食い違った場合、その差分と理由。該当なしなら見出しごと省略]

## 👮‍♂️ 動作確認 👮‍♂️

- [ ] API に破壊的な変更がない（エンドポイント削除やレスポンス変更など）
- [ ] ローカルで動作確認済み
- [ ] CI が正常に通過
- [ ] ドキュメント（README, Swagger など）が更新済み
- [ ] gemini のレビュー指摘をチェック

## マージ後 TODO

- [ ] [マージ後に実施が必要なフォローアップ、または他者への依頼。該当なしなら見出しごと省略]
```

## `tmp/` 由来の記載を持つ 2 欄

`tmp/` はコミットが hook でブロックされるため、`tmp/grill.md` / `tmp/scenario.md` / `tmp/plan.md` は **PR の diff に現れない**。上記 2 つの見出し（`## grill 決定からの変更` と `## マージ後 TODO`）は、その内容が**転記されて初めて共有される**ためのものである。

**どちらも独立見出し（`##`）で統一している** — 箇条書き項目と見出しが混在すると、参照側（`SKILL.md`）の表記と一致しなくなるため。対象リポジトリの `.github/PULL_REQUEST_TEMPLATE.md` に該当節が無い場合も、PR 本文の末尾に同じ見出しを立てる。
