# 設計材料型の調査手順と出力構成（ask skill 補助）

フェーズ 1 で**設計材料型**と判定した問い（目的・方向性・理想形・拡張性・業務シナリオを含み、答えが後工程の判断材料になる問い）に適用する。SKILL.md の照合度ラベル・検索手段の使い分け・前提の判定はそのまま適用し、ここでは設計材料型で**加える**手順と出力構成だけを定める。

## 加える調査手順

1. **実測すべき問いを切り出す**: 利用実態・件数・分布・実データでの不変条件など、コードを読んでも答えが定まらない問いを分ける。実測できればフェーズ 2 の DB 実測の行に従い、できなければ未確認事項の先頭に置く（コードから推論した値を実測値のように書くと、後工程がそれを前提に判断するため）
2. **別名で並存する同じ概念を横断する**: 題材の概念を言い換えて複数回検索する（同義語・上位概念・画面上の呼び名・テーブル名）。同じ概念が別の名前で既にあると、重複した設計になる
3. **書込経路・ガード・除外条件を網羅する**: 題材のデータを作る・変える・消す経路を grep で列挙し、各経路のガード（権限・状態チェック）と除外条件を記録する。1 経路だけを見て全体を語ると、他の入口の挙動を見落とす

## 出力構成

以下の順で書く。要旨・基準・前提の判定・未確認事項は回答全体で 1 回だけ書き（位置と書式は SKILL.md のフェーズ 4）、実測・現状・ギャップ・論点は問いごとに `## 質問 n` の下へ `###` で置く。論点は「決定」と書かない — 決めるのは後工程の `/grill`・`/design` で、ask が決定の形で書くと、その判断が検討されないまま確定事項として扱われるため。

```
## 要旨
- [結論を 3〜5 行。訂正した前提があれば最初に書く]

## 基準・前提の判定
- SKILL.md フェーズ 4 の骨格どおり

## 質問 n: [問いの要約]

### 実測
- [件数・分布・不変条件の実測結果。取得元と取得日時を併記する]
- 未実測の場合は「未実測」と明記し、実測項目を未確認事項へ回す

### 現状
- [コード・仕様から確認した現在の構造と挙動。照合度ラベル付き]
- [書込経路・ガード・除外条件の一覧]
- [別名で並存する同じ概念（あれば）]

### ギャップ
- [目的・業務シナリオの期待値と、現状との差]

### 論点
- [後工程で決める必要がある問いと、各選択肢の材料。「推奨」を書く場合も決定とは書かない]

## 未確認事項
- [実測していない項目を先頭に置く]
- [確認できなかったこと]
```
