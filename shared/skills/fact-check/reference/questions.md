# 事実の裏取りの問い

## 抜き出す主張

確かめられる形の主張だけを抜き出す。意見・方針（「〜すべき」）は抜き出さない。

| 種類 | 例 | 確かめ方 |
|---|---|---|
| 件数・数値 | 「約 600 本」「7 日」「24 時間」 | 出典の有無。コードで数えられるなら `rg -c`・`git grep -c` |
| 固有名 | ファイル名・関数・クラス・コマンド・環境変数・ジョブ名 | 1 つずつ `rg -n`。見つからなければ崩れた主張 |
| 位置 | `file:L`・節の番号 | Read で開き、書かれた内容がその行にあるか |
| コミット・PR | ハッシュ・PR 番号 | `git show --stat <hash>`・`gh pr view <n>` |
| 解決順・流れ | 「A の後に B が呼ばれる」「先頭のスロットが勝つ」 | 呼び出し元をたどる（`rg -n` で呼び出しの箇所を拾い、順に Read） |
| 言い切り | 「0 件」「必ず」「しない」「すべて」 | 反例を探す（`rg -n` で例外の経路・別の入口） |
| 道具の性質 | 「ログは 15 日残る」「上限は 1000 件」 | 対象 repo の設定・ルールの記述。無ければ未実測 |

## 仕分けの基準

- **実測（出典あり）**: 文書がコマンド・クエリ・ログ・`file:L`・コミットを出典として示している
- **見込み（出典なし）**: 数値・言い切りがあるのに出典が無い
- **推測と明記**: 文書自身が「推測」「未計測」「見込み」と書いている

見込みの主張は、判断を支えているかで重大度を決める: 判断を支える見込みは Medium（裏取りで崩れれば High）、支えない見込みは Low。推測と明記した主張は指摘にしない（測る手段を「人への問い」に書く）。

## 文脈の事実性（観点 2）

- 文脈の節が、採用案に都合のよい事実だけを並べていないか（却下案に有利な事実・採用案の弱点が文脈から抜けていないか）
- 前の ADR・別の入口の修正など、文書を書いた後に現実が先に動いた形跡が無いか（`git log --since=<文書の日付>` で関係するファイルを見る）

## 根拠の証拠（観点 5）

- 数値の根拠が、問題の性質ではなく道具の制約（ログの保持期間・料金・API の上限）から来ていないか。道具の制約なら、そう書いてあるかを見る（書いていなければ Medium。移行の判断基準にしているなら `rollout-check` と重なってよい。集約でまとめる）
- 仮説（「〜だろう」）と事実（「〜である」）を分けて書いているか

## 人への問いに返すもの

- コードに現れない運用の慣行（「当番が毎朝見る」）
- 人の判断・合意（「チームで合意済み」）
- 将来の見込み（「来年には件数が 10 倍になる」）の根拠
