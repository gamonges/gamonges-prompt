# モード: implement

## 対象

要件が見えている機能の追加・変更。何を作るかは決まっており、どこをどう変えるかを詰める段階で使う。

## テンプレート

```markdown
---
mode: implement
title: {題材}
base_commit: {git rev-parse HEAD}
---

# {題材}

## 目的と決めたいこと
<!-- 必須: この調査・壁打ちの結果で何を決めるか -->

## 対象
<!-- 必須: 対象の repo・機能・画面 -->

## 既知の前提
<!-- 正しいと思っていること。ask が正しい／訂正／確認不可を判定する -->

## 外部データ源と取りたいもの
<!-- DB 実測・タスク管理・設計図・ADR など、どこから何を取りたいか -->

## スコープ外

## 要件
<!-- 必須: 何ができるようになればよいか -->

## 受入条件の素案
<!-- 完了をどう判定するか。粗くてよい（design が Given/When/Then に起こす） -->

## 関連チケット

## 質問
<!-- 必須: 1 行 1 問。区切りは箇条書きか ===== -->
```

## ask の観点

- 既定の型: **事実確認型**
- 変更対象に至る書込経路・ガード・除外条件を grep で網羅する。1 経路だけ直して他の入口が残るのが典型的な取りこぼし
- 既存の同種実装を探し、従うべきパターンとして示す
- 影響範囲（呼び出し元・同じデータを読む箇所）を列挙する

## grill の観点

- 受入条件・入口と出口・rollout（段階公開やフラグの要否）を既定で先に確かめる候補にする

## design の観点

- **先行ステップの候補**: なし
- **重点を置くセクション**: なし
- **アンチゴールに加える項目**: なし

## implement の観点

既定（追加なし）。
