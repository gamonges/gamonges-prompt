# コメント案

検証を通った指摘から、作者に伝えるコメントの案を作る。**投稿しない**（投稿はオーナーの OK の後に呼び出し側が行う）。

## コメントのラベル

コメント案には必ずこの体系でラベルを付ける。ラベルは「レビュイーに何をしてほしいか」で付ける（重大度の言葉ではなく、行動の言葉）。コメントの先頭に 1 つだけ付ける。

| ラベル | 意味（レビュイーが取る行動） | AI の内部の重大度との対応 |
|---|---|---|
| `[must]` | 直さないとマージできない | 高 |
| `[want]` | できれば直してほしい。相談・後続 PR でも可 | 中 |
| `[nits]` | 好みの問題。直すかは任意 | 低 |
| `[ask]` | 本当に答えを知りたい質問。直すかは答え次第 | — |
| `[fyi]` | 参考情報。対応は不要 | — |

- `[must]` でも本文は柔らかく書く（例:「〜しないと〇〇が起きそうなので、直したいです」）。
- 初めて見るレビュイーのために、PR 全体へのコメント（レビュー本文）の末尾に凡例を 1 行添える:「ラベル: [must] マージ前に必要 / [want] できれば / [nits] 任意 / [ask] 質問 / [fyi] 参考」

## 書き方

- 観点ファイル（`--lenses` / `PR_EXPLAIN_LENSES_DIR` の `<repo 名>.md`）に `## コメント案の書き方` の節があれば、それに従う（ラベルの体系より観点ファイルの書き方を優先する点はない。両方に従う）

- 1 コメント = 1 論点。同じ種類の指摘（共通部品の不使用など）はまとめて PR 全体へのコメントにする
- 行コメントにするものは、置く `path` と行の範囲を見出しに書く。行番号は検証（`verify.md`）で引き直した head の値
- 事実（どこで何をしているか）→ なぜ気になるか（規約の該当箇所・オーナー方針）→ 提案、の順に書く。提案は 1 つに絞らず、「段階 1 はこのままで TODO を残す」など作者が選べる逃げ道も添える
- 作者がすでに PR 本文や既出のコメントで「据え置く」と説明しているものは、蒸し返さない。既出のコメントはフェーズ 7 まで読まないので、案はフェーズ 5 で一度作り、フェーズ 7 の後に見直して消す・書き直す（PR 本文はフェーズ 1 で読んでいるので、本文で説明済みのものはフェーズ 5 で外す）
- 断定できないもの（検証で判定不能）は「〜でしょうか」と質問の形にする
- 口調は依頼・相談の丁寧語。重大度の語（高・中・低）や「AI の指摘」という語は本文に出さない（ラベルの対応表の「高・中・低」は案を作るときの目安で、本文には出さない）
