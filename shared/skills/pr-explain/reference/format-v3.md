# 解説の形式（v3）

読み手はレビュー依頼を受けた人間（オーナー）。PR が多すぎて全実装は読めないので、「AI のレビューだけで通してよい部分」と「人間が判断する部分」を分ける。v3 は blind 試行（10 PR を既存のレビューを見ずに解説し、実際の人間の指摘と後続の commit で採点）の結果で改めた版。

## 区分

| 区分 | 意味 | 例 |
|------|------|----|
| A | AI のレビューだけで通してよい。戻すのが容易で影響が局所 | リファクタ、テスト、文言、**設定値 1 個の変更で影響範囲が明確なもの** |
| B | 意図と指定箇所だけ人間が読む | 既存の型どおりの追加・修正 |
| C | 人間がしっかり読む。戻せない、または影響が広い | 下の機械的ルールに当たるもの |

### 機械的ルール（判断より優先）

1. 次のどれかを**変える**なら C: IAM・認可の範囲、DB のスキーマ・マイグレーション・backfill、公開 API / RPC / イベントの契約、テナント境界
   - 「変える」は、権限の付与・剥奪、スキーマの変更、契約の型・意味の変更、テナントの分け方の変更を指す
   - 契約を**使うだけ**（新しい API を client に登録して呼ぶ、既存の型を import する）、権限スコープで**表示を出し分けるだけ**（サイドバーの項目を隠す等）では C にしない。そのときは「契約・権限に触れるが変えていない」と理由に書き、確かめる点（backend 側でも検査しているか等）を項目 5 に回す
   - 共通部品が暗黙に足す権限（例: ARN を渡すと `sts:AssumeRole` を付けるヘルパー）も「変える」に数える。差分に IAM の文字が無くても、実効の権限が広がるなら C
2. 項目 6 に重大度「高」が 1 件でもあれば C（解説が高を付けたまま B にした PR が、実際に人間から同じ指摘を受けた）
3. 「本番に効く」だけでは C にしない（本番の設定値 1 個で影響が明確なら A。B にして過大だった例がある）

区分の理由には、効いたルールの番号を書く（例: 「C（ルール 1: IAM の範囲を変える）」）。軽い版での当て方（ルール 2 を当てない・決まらなければ C に倒す）は `../SKILL.md` の軽い版の節。

## 各項目の書き方

1. **区分と理由** 1 行
2. **意図の要約** 3 行以内
3. **本文と差分の食い違い**: PR 本文・タイトル・チケットが「やった」と書いているのに差分に無いもの、逆に本文に無いのに差分にある大きな変更。本文の主張を一覧にして、head のどこで担保されるかを 1 行ずつ当てる。なければ「なし」
   - 本文が先に最終形を書き、head がまだ追いついていないことが多い（blind 試行では全件が後続の commit で足された）。「未実装」と断定せず「head の時点では無い」と書く
4. **人間が読むべき箇所** 3〜5 個: `path:L行` ＋ そこで人間が判断すべき問い 1 行。フル版では図解のピンの番号と揃える
   - 仕様の判断（どちらを優先するか、何を絞らないか）、全画面・全項目に効く共通部品の変更、戻しにくいものを優先する
5. **差分の外で効くもの**: 呼び出し元、共通部品が暗黙に足すもの、他リポジトリ（デプロイ順、契約の相手）、外部 API の仕様。それぞれ「何を確かめるべきか」1 行
6. **AI の指摘**: 型・規約・テスト・横展開の漏れ・エッジケースなど。重大度（高 / 中 / 低）と `path:L行` を付ける。なければ「なし」
   - **UI の変更があるとき必須**: キーボード操作・タッチ操作・フォーカス・スクリーンリーダーで、変更した UI が使えるか（無効状態の理由が見えるか、ツールチップがフォーカスで出るか、色だけで区別していないか）。フェーズ 2 で読んだ規約ファイル（コーディング規約・デザインシステムの a11y の節など）の該当箇所を根拠に書く
   - 除外・保留・スキップを足す変更では、兄弟処理（同じデータを触る別経路: 通常の更新・差し替え・孤児の削除など）への二次影響を列挙する
   - 確証が無いものは「要確認」と書き、確かめ方を添える。確信度で握りつぶさない（フィルタはオーナーが行う）
7. **読んだ規約ファイル**: SKILL.md のフェーズ 2 の表をそのまま載せる。読めなかったもの・範囲を絞ったものも書く
8. **repo 別の観点**: 観点ファイルの `## 観点` の観点ごとの小見出しと、`./repo-lenses.md` の汎用の観点。観点ファイルが無ければ「repo 固有の観点なし（探した場所: …）」と書いて汎用の観点だけ
9. **既出の指摘**: フェーズ 7 で足す
