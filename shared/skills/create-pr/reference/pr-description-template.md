# PR 本文テンプレート

`/create-pr` Phase 5 で PR 本文を生成する際の構成。`.github/PULL_REQUEST_TEMPLATE.md` のフォーマットに従う。

**Notion Page ID の処理**は `SKILL.md` の「Notion Page ID によるリファレンス付与」を参照（抽出ルールと本文構造例はそちらが SSOT。本ファイルでは再宣言しない）。

テンプレート構成:

```markdown
## 🗺️ 全体像（…）   ← 該当時のみ。下の「全体像ブロック」

## 📝 PR 概要 📝

- **目的**:
  - [機能追加/仕様変更/バグ修正/リファクタリング]
- **関連リンク**:
  - [関連する Issue、Notion、Figma など]
- **変更点の概要**:
  - [主要な変更内容を箇条書き]

## grill 決定からの変更

- [実装が `tmp/grill.md` / `tmp/scenario.md` の照合対象と食い違った場合、その差分と理由。該当なしなら見出しごと省略]

## 👮‍♂️ 動作確認 👮‍♂️

- [ ] API に破壊的な変更がない（エンドポイント削除やレスポンス変更など）
- [ ] ローカルで動作確認済み
- [ ] CI が正常に通過
- [ ] ドキュメント（README, Swagger など）が更新済み
- [ ] gemini のレビュー指摘をチェック

## マージ後 TODO

- [ ] [マージ後に実施が必要なフォローアップ、または他者への依頼。該当なしなら見出しごと省略]
```

## `tmp/` 由来の記載を持つ 2 欄

`tmp/` はコミットが hook でブロックされるため、`tmp/grill.md` / `tmp/scenario.md` / `tmp/plan.md` は **PR の diff に現れない**。上記 2 つの見出し（`## grill 決定からの変更` と `## マージ後 TODO`）は、その内容が**転記されて初めて共有される**ためのものである。

**どちらも独立見出し（`##`）で統一している** — 箇条書き項目と見出しが混在すると、参照側（`SKILL.md`）の表記と一致しなくなるため。対象リポジトリの `.github/PULL_REQUEST_TEMPLATE.md` に該当節が無い場合も、PR 本文の末尾に同じ見出しを立てる。

## 意味のカードがあるとき

`./tmp/meaning-card.md` があるとき（`SKILL.md` の Phase 4.5.4）だけ、既存の節に次の 2 つを入れる。新しい `##` の節は足さない。カードが無いときの本文は上のテンプレートのまま。

- **前提**: カードの (d) 外部システムへの前提を、「📝 PR 概要」の末尾（変更点の概要の後）に `- **前提**:` の項目として 5 行まで書く。超えた分は `<details><summary>前提の残り</summary>` に畳む
- **ケースから作る動作確認**: カードの (e) ケースの表の 1 行を 1 項目（`- [ ] <ケース>: <操作> → <期待>`）にして、「👮‍♂️ 動作確認」の先頭に 10 行まで置く。超えた分は `<details>` に畳む。既存の固定の項目はその後ろに残す
- 上限（5 行・10 行）は暫定（今の本文の分量の実測が無い）
- 書かないもの: カードの (a)〜(c)・推奨で進めた判断・(f)（`/create-pr` を打つ前に人が見る材料）と、計画の内部 ID（段の名前・ステップ ID・`Q-<n>`・`K-<n>`）

## 全体像ブロック

レビュアーが PR を開いたとき、対応の全体像と、その PR が担う部分が一目で分かるようにするためのブロック。シリーズ（複数の PR に分けた対応）の PR と、単独の PR の両方で同じ語彙を使う。

- **置き場所**: 本文の先頭。ref 行があればその下（空行を 1 行挟む）。ブロックの後は `---` の行で区切る
- **書き手**:
  - シリーズの PR: `series-sync` が目印（`<!-- series-overview:begin -->`〜`<!-- series-overview:end -->`）つきで書く。create-pr・stack-pr-submit は本文に入れない（PR 番号が作成前に分からず、兄弟の PR も同時に更新するため）。目印と置き換えの規則は `../../series-sync/reference/series-format.md`
  - 単独の PR: create-pr・stack-pr-submit が目印なしで書く
- **見出しと凡例**: `## 🗺️ 全体像（{対応の名前}）` の直後に「**この PR（#N）が担う部分を黄色で示しています。** 灰色は同じシリーズの別の PR、点線はシリーズの外です。」。単独の PR では本文を書く時点で番号が決まらないので「**この PR が担う部分を黄色で示しています。** 点線は変えない前後の処理です。」にする。シリーズでないスタックの PR では「**この PR が担う部分を黄色で示しています。** 灰色は同じスタックの別の PR、点線はスタックの外です。」にする
- **mermaid**: `flowchart LR`。ノードは PR ではなく**処理の流れの段**にする（PR をノードにすると、流れのどこを直したかが読めない）
  - ラベルは `担当 PR の番号 + 説明<br/>補足`（単独の PR では番号を書かない）
  - 1 つのノードを 2 本の PR が触るときも、強調は主担当の 1 本だけにし、もう 1 本はラベルの括弧に書く（例: `共通の後処理<br/>（#12 の掃除を含む）`）
  - classDef は次の 3 行で固定する（値も変えない。PR の間で色がずれないため）:

    ```
    classDef cur fill:#ffe082,stroke:#f57f17,stroke-width:3px,color:#000
    classDef other fill:#eceff1,stroke:#90a4ae,color:#455a64
    classDef ext fill:#ffffff,stroke:#bdbdbd,stroke-dasharray:4 3,color:#616161
    ```

  - `cur` = この PR が担う段、`other` = 同じシリーズ（スタックの PR では同じスタック）の別の PR の段、`ext` = シリーズ（単独の PR ではこの PR、スタックの PR ではスタック）の外の段
- **表（シリーズのみ）**: `| | PR | リポジトリ | 領域 | 直すもの | 解決する事象 | 順序 |`
  - 1 列目はこの PR の行だけ 👉、PR 列はこの PR の行だけ太字
  - リポジトリ列は、シリーズが複数のリポジトリにまたがるときだけ置く。別のリポジトリの PR は `owner/repo#N` と書く（GitHub が相互参照のリンクにする）
  - PR にしない作業は、PR 列を空にして「リポジトリ名＋内容」の行にする
- **注記（シリーズのみ）**: 表の下に箇条書きで「順序の理由」と「このシリーズの外」（別の対応の PR・PR にしない作業）
- **書かないもの**: 計画の内部 ID（段の名前・ステップ ID）。上の「`tmp/` 由来の記載を持つ 2 欄」と同じく、レビュアーは `tmp/` を見られないため
- **単独の PR の図**: その PR が触る処理の流れを描き、変える段を `cur`、変えない前後の段を `ext` にする（`other` は使わない）。PR の一覧表と注記は置かない
- **スタックの PR の図**（シリーズでないスタック。stack-pr-submit が書く）: スタック全体で 1 つの処理の流れを描き、PR ごとに強調だけを変える。その PR が変える段を `cur`、同じスタックの別の PR が変える段を `other`、スタックの外の段を `ext` にする。凡例は上のスタックの PR のもの。ラベルに番号を書かない（作成前に番号が決まらない）。PR の一覧表と注記は置かない
  - **図にする処理の流れが無い変更**（文言・依存の版・設定値だけの変更など）では、ブロックごと省き、省いた理由を完了報告に 1 行書く

単独の PR の例:

````markdown
## 🗺️ 全体像（注文の取込の重複を除く）

**この PR が担う部分を黄色で示しています。** 点線は変えない前後の処理です。

```mermaid
flowchart LR
  RECV["ファイルを受ける"]
  SAVE["注文を保存する<br/>（重複を除く）"]
  NOTIFY["取込結果を通知する"]
  RECV --> SAVE --> NOTIFY
  classDef cur fill:#ffe082,stroke:#f57f17,stroke-width:3px,color:#000
  classDef other fill:#eceff1,stroke:#90a4ae,color:#455a64
  classDef ext fill:#ffffff,stroke:#bdbdbd,stroke-dasharray:4 3,color:#616161
  class SAVE cur
  class RECV,NOTIFY ext
```

---
````

シリーズの PR の完成形（置換子つき）の例は `../../series-sync/reference/series-format.md` にある。
